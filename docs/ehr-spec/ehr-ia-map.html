Global sitemap

Eight top-level destinations in a persistent left rail. The patient chart is a context, not a destination: it opens from anywhere and pins a patient banner until closed. Dots show which roles use each screen.

Chart & encounter anatomy

The chart is a three-pane workspace. Identity and safety data sit in a banner that never scrolls away; the encounter note sits in the centre; the right pane is a context drawer that changes with what you are doing.

Encounter workspace (centre)

  • Header: visit type, provider, location, date of service, POS, status chip (Draft → Ready to sign → Signed → Addended)
  • Section tabs: Pre-chart · Rooming · Note · Orders · Rx · Dx & coding · Charges · AVS · Sign
  • Note body: CC, HPI, ROS, PE, data reviewed, assessment & plan by problem; templates, smart phrases, voice / ambient draft with source highlighting
  • Inline order entry per problem so diagnosis linkage is captured at the moment of ordering
  • Autosave every keystroke burst; draft survives session timeout

Context drawer (right)

  • Mini summary: active problems, meds, last vitals, recent results
  • CDS cards: care gaps, drug alerts (interruptive only when severe)
  • Order search + favourites + order sets
  • Coding assistant: E/M by MDM or time, Dx specificity prompts
  • Previous note for copy-forward with diff highlighting

Action bar (sticky bottom)

Save draft · Pend for provider (MA) · Route for co-sign · Sign & lock · Sign & send charges · Print AVS. Signing runs a pre-flight check: unlinked orders, unsigned Rx, missing Dx on charges, open critical results.

Patient portal & app

Mobile-first, plain language at a 6th–8th grade reading level, WCAG 2.1 AA. Proxy access for parents and caregivers with age-based rules for adolescents.

UX patterns & patient safety

Cross-cutting rules that every module follows. Most of these exist because of known EHR-related safety events.

Integrations & compliance

Where regulation and external systems touch the IA. Verify current ONC/ASTP certification criteria and CMS program rules at build time; these change yearly.
